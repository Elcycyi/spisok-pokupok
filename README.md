# Список покупок на React

Домашняя работа: список товаров с названием и ценой, можно добавлять и удалять,
внизу считается общая стоимость.

## Запуск

```
npm install
npm run dev
```

Откроется на http://localhost:5173

## Что требовалось и где оно лежит

| Требование | Где смотреть |
|---|---|
| Сделать через React | весь проект, Vite + React 19 + TypeScript |
| Отдельный компонент для элемента списка | `src/components/ProductItem.tsx` |
| Использовать state | `useState` в `src/App.tsx` — три штуки |
| Использовать props | `ProductItem` получает `product` и `onDelete` |
| Добавлять товары | форма внизу `App.tsx`, функция `handleSubmit` |
| Удалять товары | кнопка в `ProductItem`, функция `handleDelete` |
| Общая стоимость | `const total = products.reduce(...)` |

## Разбор: что отвечать, если спросят

**Что такое state и зачем он тут?**
`useState` — это память компонента, за которой React следит. Как только
значение меняется через `setProducts`, React перерисовывает страницу.
Обычная переменная так не умеет: изменить её можно, но экран не обновится.

**Что такое props?**
Данные, которые компонент получает снаружи, от родителя. `ProductItem` сам
ничего не знает про список — ему передают один товар и функцию удаления.
Описаны они интерфейсом `ProductItemProps`.

**Почему `[...products, newProduct]`, а не `products.push(newProduct)`?**
Главный вопрос по этой теме. React сравнивает не содержимое массива, а ССЫЛКУ
на него. `push` меняет массив на месте — ссылка остаётся прежней, React решает,
что ничего не изменилось, и перерисовки НЕ БУДЕТ. Запись через `...` создаёт
новый массив с новой ссылкой, и React видит изменение.

**Зачем `key` у элемента списка?**
По нему React понимает, какой элемент какой, когда список меняется. Без `key`
он не знает, что именно добавилось или удалилось, и перерисовывает лишнее.
В консоли при этом висит предупреждение «Each child in a list should have
a unique key».

**Почему `id: Date.now()`?**
Нужен уникальный номер. `Date.now()` возвращает количество миллисекунд и
для списка покупок годится. Брать `products.length` нельзя: удалил товар из
середины — и длина совпадёт с чужим id, получатся одинаковые ключи.

**Как считается сумма?**
`reduce` проходит по массиву и накапливает результат: начинает с нуля и
прибавляет цену каждого товара. Отдельно в state её хранить не нужно — она
пересчитывается сама при каждой перерисовке.

**Как работает удаление?**
`filter` возвращает НОВЫЙ массив, куда попадают все товары, кроме того,
у которого совпал `id`. Снова новый массив — снова новая ссылка — снова
перерисовка.

**Почему `e.preventDefault()` в форме?**
Без него браузер при отправке формы перезагрузит страницу целиком, и всё
состояние сбросится.

**Что такое «контролируемый input»?**
У поля есть `value={name}` и `onChange`. Значение живёт в state, а не внутри
самого поля. Поэтому после добавления товара достаточно написать `setName("")`,
и поле очистится само.
